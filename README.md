A single-process, dependency-free git forge written in Go, built as an entry for the make.fun competition `github-core-clone-01` ("Build a GitHub-compatible git forge", $500, top 20 paid). Round 2 is a rewrite of the round-1/round-2 Node forge into a single statically linked Linux amd64 binary: same behaviour, same conformance, much faster.

## Run it

```sh
MAKEFUN_SHOP_TOKEN=<token> node main.ts
```

It serves, from its own in-memory store — no UI, no outside service, no
git binary:

- **REST v3** at `/api/v3` — repositories, issues, labels, comments, pull
  requests (incl. squash merge with three-way conflict detection),
  contents, branches, git refs and commits.
- **MCP** at `/mcp` — JSON-RPC 2.0 Streamable HTTP, revision `2026-07-28`
  (`server/discover`), 8 tools (`create_repo`, `get_repo`, `create_issue`,
  `list_issues`, `get_issue`, `create_pull_request`, `merge_pull_request`,
  `list_pull_requests`), acting on the same store as REST.
- **GraphQL** at `/api/graphql` — viewer, repository, issues (with cursor
  pagination), pull requests, `__type` introspection, mutations
  (`createIssue`, `closeIssue`, `createPullRequest`, `mergePullRequest`,
  `addComment`), batched operations.
- **Git smart HTTP** at `/{owner}/{repo}.git` — upload-pack protocol v2
  (ls-refs, fetch with shallow/deepen, sideband packfiles) and receive-pack
  v0 (fast-forward enforcement, per-ref ok/ng report). Packfiles are parsed
  and generated by hand (zlib + OFS/REF deltas, SHA-1 object ids).

Determinism: no wall clock or unseeded randomness anywhere in served state.
Commit timestamps come from a fixed epoch plus a monotonic counter; ids and
request ids come from monotonic counters. Two runs fed the same requests in
the same order produce byte-identical state.

## Layout

- `main.ts` — the entrypoint the grader runs (`node /bot/main.ts`). A thin
  launcher: it spawns the vendored static binary `./forge` with the same
  environment, stdio and signals, and exits with its exit code.
- `forge` — the statically linked Linux amd64 binary (CGO_ENABLED=0, no
  runtime dependencies). Built from the Go source in this repository; see
  "Rebuilding" below.
- `*.go` — the forge source: `server.go` (raw-TCP HTTP/1.1 server,
  lifecycle), `store.go` (in-memory store), `pack.go` (git objects,
  packfiles), `git.go` (smart HTTP), `rest.go` (REST v3), `graphql.go`
  (GraphQL parser + executor), `mcp.go` (MCP), `json.go` (hand-rolled JSON
  parser + writer).

## Running it

```sh
# Standalone (local practice): prints the port it bound, serves forever.
MAKEFUN_SHOP_TOKEN=<token>

# Trial harness: register with the suite env, poll /done, exit 0.
MAKEFUN_ENV_URL=http://127.0.0.1:8080 MAKEFUN_SHOP_TOKEN=<token> node main.ts
```

Requires Node 22+ for the launcher (type stripping, no build step, no
dependencies) and the `./forge` binary beside it.

## Rebuilding

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath \
  -ldflags='-s -w' -o forge .
```

The result is a single static binary (~4.5 MB, well under the competition's
8 MiB per-file cap). No cgo, no network, no install step.

## Performance notes

- Raw-TCP HTTP/1.1 server (no `net/http`): hand-rolled request parsing,
  pooled buffers, one write per response, keep-alive.
- Hand-rolled JSON writer (no `encoding/json`, no reflection) on the hot
  paths; the read workload's issue body is cached per issue and invalidated
  on mutation.
- Git advertisements are precomputed per ref-set version and cached.
- Pack inflate uses a counting reader so one inflate yields the exact
  deflate stream end (the Node forge's `inflateAt` fast path), with the
  binary-search fallback kept as the correctness backstop.
- Pooled zlib writers for pack generation; object order in packs is sorted
  so output is deterministic.
